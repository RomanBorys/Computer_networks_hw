### Аналіз результату

Основним мережевим інтерфейсом Ubuntu є **`enp0s3`**. Це віртуальний Ethernet-інтерфейс, створений для Ubuntu у середовищі VirtualBox.

| Параметр        | Значення                                           |
| --------------- | -------------------------------------------------- |
| Інтерфейс       | `enp0s3`                                           |
| Тип підключення | Ethernet, віртуальний мережевий адаптер VirtualBox |
| MAC-адреса      | `08:00:27:4c:ae:df`                                |
| IP-адреса       | `10.0.2.15`                                        |
| Маска           | `/24` або `255.255.255.0`                          |
| Broadcast       | `10.0.2.255`                                       |
| Gateway         | `10.0.2.2`                                         |
| Host            | `10.0.2.15`                                        |

### MAC-адреса

MAC-адреса мережевого інтерфейсу `enp0s3`:

08:00:27:4c:ae:df

MAC-адреса належить до 2-го рівня моделі OSI — канального рівня (Data Link Layer). Вона використовується для ідентифікації мережевого інтерфейсу в локальній мережі.

### IP-адреса

IP-адреса інтерфейсу `enp0s3`:

10.0.2.15

Це приватна IPv4-адреса, яка використовується у внутрішній мережі VirtualBox.

IP-протокол працює на 3-му рівні моделі OSI — мережевому рівні (Network Layer).

### Маска мережі

У результаті команди вказано:

/24

Це відповідає масці:

255.255.255.0

Маска визначає, яка частина IP-адреси належить мережі, а яка — конкретному хосту. Вона використовується на 3-му рівні моделі OSI.

Для мережі `10.0.2.0/24`:

* адреса мережі: `10.0.2.0`;
* діапазон адрес хостів: `10.0.2.1 – 10.0.2.254`;
* broadcast: `10.0.2.255`.

Таким чином, у цій мережі доступно 254 адреси для хостів.

### Broadcast

Broadcast-адреса:

10.0.2.255

Вона використовується для надсилання даних усім пристроям у межах локальної мережі `10.0.2.0/24`.

### Gateway

Gateway визначається з результату команди `ip r` і має адресу:

10.0.2.2

Це шлюз за замовчуванням, через який Ubuntu може передавати трафік за межі своєї локальної мережі.

### Host

Моя адреса хоста в локальній мережі:

10.0.2.15

Вона ідентифікує конкретний пристрій (у цьому випадку віртуальну машину Ubuntu) у мережі `10.0.2.0/24`.


## Завдання 2. Дослідження маршрутизації

Для визначення маршрутів була використана команда:

ip r

### Результат виконання команди

default via 10.0.2.2 dev enp0s3 proto dhcp src 10.0.2.15 metric 100
10.0.2.0/24 dev enp0s3 proto kernel scope link src 10.0.2.15 metric 100
172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1 linkdown

### Аналіз результату

Основним маршрутом є:

default via 10.0.2.2 dev enp0s3 proto dhcp src 10.0.2.15 metric 100

З нього можна визначити:

| Параметр            | Значення    |
| ------------------- | ----------- |
| Gateway             | `10.0.2.2`  |
| Мережевий інтерфейс | `enp0s3`    |
| Протокол            | `DHCP`      |
| IP-адреса джерела   | `10.0.2.15` |
| Metric              | `100`       |

`default` означає маршрут за замовчуванням. Якщо система не має більш конкретного маршруту для певної мережі, пакети будуть відправлятися через цей маршрут.

`via 10.0.2.2` означає, що шлюзом за замовчуванням є адреса `10.0.2.2`.

`dev enp0s3` показує, що для передачі пакетів використовується мережевий інтерфейс `enp0s3`.

`proto dhcp` означає, що цей маршрут був отриманий за допомогою DHCP (Dynamic Host Configuration Protocol).

Таким чином, IP-адреса `10.0.2.15` та відповідні мережеві параметри були отримані автоматично через DHCP.

Також присутній маршрут:

10.0.2.0/24 dev enp0s3 proto kernel scope link src 10.0.2.15 metric 100

Він відповідає локальній мережі `10.0.2.0/24`.

Окремо присутній маршрут:

172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1 linkdown

Це мережа Docker. Інтерфейс `docker0` у цей момент не використовується для основного мережевого підключення.


## Завдання 3. Знаходження публічної IP-адреси

Для визначення публічної IP-адреси була використана команда:

curl ifconfig.io

### Результат виконання команди

73.209.204.193

Отже, моя **публічна IP-адреса**:

73.209.204.193

### Порівняння локальної та публічної IP-адрес

Локальна IP-адреса Ubuntu:

10.0.2.15

Публічна IP-адреса:

73.209.204.193

Вони не однакові.

Причина полягає в тому, що `10.0.2.15` є приватною IP-адресою. Вона використовується всередині локальної мережі VirtualBox і не маршрутизується безпосередньо через Інтернет.

Для виходу в Інтернет використовується технологія NAT (Network Address Translation). У моєму випадку VirtualBox використовує режим NAT, тому віртуальна машина має внутрішню адресу `10.0.2.15`, а зовнішні ресурси бачать публічну IP-адресу `73.209.204.193`.

Схематично це можна представити так:

Ubuntu
10.0.2.15
    |
    | локальна мережа
    v
VirtualBox NAT
10.0.2.2
    |
    | NAT
    v
Інтернет
    |
    v
73.209.204.193
публічна IP-адреса

NAT дозволяє декільком пристроям або віртуальним машинам використовувати одну публічну IP-адресу для доступу до Інтернету. Таким чином, локальна адреса `10.0.2.15` використовується всередині приватної мережі, а `73.209.204.193` є адресою, яку бачать зовнішні Інтернет-ресурси.


## Висновок

Під час виконання домашнього завдання було досліджено мережеву конфігурацію Ubuntu за допомогою команд `ip a`, `ip r` та `curl ifconfig.io`.

Було визначено, що основним мережевим інтерфейсом є `enp0s3`, його MAC-адреса — `08:00:27:4c:ae:df`, а локальна IPv4-адреса — `10.0.2.15/24`.

Шлюзом за замовчуванням є `10.0.2.2`, а мережеві параметри були отримані через DHCP. Публічна IP-адреса `73.209.204.193` відрізняється від локальної, оскільки між віртуальною машиною та Інтернетом використовується NAT.

Таким чином, було закріплено розуміння локальних і публічних IP-адрес, MAC-адрес, маски мережі, gateway, broadcast, DHCP та принципу роботи NAT.
